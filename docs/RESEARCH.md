### 送ったものは見えるべきか (自分の送信のあとの位置)
- 入り口: 「送った返信は画面に見える」は当たり前と思っていた。よく使う作業 (D-046) の「返す」を決めるときに、
  このアプリでは読んでいる途中で返すと、送った返信が画面の外 (一番下) に出て見えないことに気づいた (ChannelScreen は最下部にいるときだけ追従する)
- 確かめたこと: Element X Android (`develop` の `TimelineView.kt`) は、新しい出来事が自分のもの (`NewEventState.FromMe`) なら、
  読んでいる位置に関係なく一番下へ送る (`scrollToBottom(force = true)`。11 項目より離れていれば一気に、近ければ動かして)。
  他人のものは、下から 3 項目以内にいてライブのときだけ追従し、そうでなければ「最下部へ」のボタンに未読の印を付ける
- 推測: 自分が送ったものが見えないと、送れたかどうかを確かめるために、もう一度スクロールする手間が生まれる (P-3)。e2e の `reply` で見えるかを記録して確かめる
- e2e の reply で、判定を直した後 4 回とも返信が見えないことを確かめた (#57)。直す作業は #58
- 直した (D-051)。送れたら、そのメッセージが一覧に載るのを待ってから送る。最新側を読み込んでいなければ読み込み直す

### 自分の送信で一番下へ送るのを、嫌がる人はいないか
- 入り口: D-051 で「自分が送ったら一番下へ」を当たり前として直した。逆の意見が無いかを疑った
- 確かめたこと (検索結果の見出しと要約まで。原文は開いていない): 「送ると一番下へ飛んで、読んでいた位置を失う」という不満は、
  主に AI のチャット (Cursor・VS Code の拡張など) で出ている。そこでは長い答えが流れ込むのを読みながら、上の方も読み返すため
- 確かめたこと: MUI の Chat の説明 (mui.com) は、この環境から開けなかった (ネットワークの設定)。検索の要約では「自分の送信では常に送り、他は下から離れていれば止める」
- 推測: 人どうしのチャットで送るのは短い文で、送れたかを見たい。AI のチャットとは、送った後に見たいものが違う。
  ただ「返信を書く間、元のメッセージを見ていたい」はあり得る。送った後に元の位置へ戻す手段 (返信の引用を押すと元へ飛ぶ) はもうある
